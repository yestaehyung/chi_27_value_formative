반영구현실동작 확인 (8/11 실측 대화)
바로 추천에이전트 기본 행동 = 되묻기가 아닌 추천. 행동 판단이 모호하면 추천으로 폴백. 숨은 기준 파악은 질문 공세 없이 대화·반응에서 배경 추론첫 턴 "캠핑용 스피커, 시끄러운 건 부담" → 즉시 5개 추천 + "마음에 드는 쪽을 골라주시면 다음 추천을 맞춰볼게요" (되묻기 0회)
구조화 표현말풍선에 표·불릿·번호목록 렌더링 추가, 비교 요청일 때만 사용. 회귀 테스트 12개로 고정비교 질문("첫 번째랑 두 번째 차이?")에 두 후보의 확인된 스펙·평점을 대조해 답변
선택 가능한 정보추천 카드마다 추천 이유 + 기준 부합점(✓)·미흡점(−) + 가격·평점·리뷰카드 예: "IP67 방수로 야외 사용에 안전 / 출력 사양 미기재로 소리 크기를 정확히 알 수 없음"

03에이전트 답변의 구조화 (표·목록)

평문만 허용하던 말풍선이 이제 구조를 렌더링합니다.

  • 프론트에 전용 렌더러(StructuredText) 신설 — 불릿·번호 목록·표·굵게 4가지만 렌더하고, 그 외 마크다운(제목·코드블록 등)은 백엔드가 계속 제거합니다.
  • 프롬프트 원칙: 기본은 사람처럼 한두 문장, 비교 요청 등 구조가 이득일 때만 표를 씁니다. 상품 카드가 이미 보여주는 정보(가격·평점)는 표로 중복하지 않습니다.
  • 부수 수정 — 카드 위치 오안내 버그: 프롬프트의 금지 예시("오른쪽 패널")가 오히려 그 단어를 심어 12%(5/40)가 잘못된 방향 안내를 했습니다. 오염원 제거 후 0/40. 회귀 테스트로 고정.

05추천 알고리즘

발화 → 1단계 의미 검색 (선택 카테고리 안에서만, 후보 30개) → 가격·속성 필터 → 2단계 LLM 재정렬 (조건 집행 · 강점이 다른 5개 구성) → 카드 5개 노출
  • 역할 분담 — 1단계 검색은 관련성만 보고, "30만원 이내"·"무선만" 같은 조건 집행과 서로 다른 강점의 조합 구성은 2단계 LLM이 담당합니다.
  • 부정 표현("시끄러운 건 싫어요")은 검색어에 넣지 않고 별도 조건 메모로 2단계에 전달합니다 — 의미 검색이 부정을 이해하지 못하는 알려진 한계를 우회.
  • 신규 상품은 이미지에서 뽑은 시각 특징까지 넣어 검색 색인을 만들었습니다 — "빨간 후드티" 같은 눈으로 보는 조건의 질의에 유리.
  • 조건을 지키는 후보가 5개 미만이면 그만큼만 정직하게 노출합니다 (조건 위반 상품으로 칸을 채우지 않음).
